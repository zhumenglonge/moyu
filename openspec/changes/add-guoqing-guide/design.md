# Design

## Context

动机与范围见 proposal.md - Why / What Changes；对外行为契约见 specs/guoqing-guide/spec.md。现状：项目已有 11 个自包含模块，changsha 模块（`games/changsha/`）提供了"数据池数组 → innerHTML 渲染 → 剪贴板复制"的成熟范式，本栏目在结构上模仿它，但把"随机拼装"换成"静态全量展示"。硬约束（零依赖、相对路径、`style.css` 只追加、`common.js` 复用）见项目上下文，不再复述。

## Goals / Non-Goals

**Goals:**
- 八条路线情报卡以手机竖屏为主视角可读、可比（朋友们大概率微信群里点开）。
- 路线数据与渲染逻辑分离，明年国庆翻新时只改数据数组不动渲染代码。
- 倒计时在任何日期打开页面都有合理文案，无"空窗期"。

**Non-Goals:**
- 不做投票、评论、分享统计等任何需要写能力的功能（探索阶段已裁决）。
- 不做随机生成/换一换交互——攻略的价值在于信息完整而非随机趣味。
- 不预设五一/春节等其它假期复用（数据结构不为此优化）。

## Decisions

### D1: 数据结构按"路线"分组而非"时段槽位"
changsha 的 `SPOTS` 按时间槽（morning/lunch/...）分组再随机抽取；本栏目改为 `ROUTES` 数组，每个元素即一条完整路线：
```js
{ id, icon, name, tagline, crowd: 1-5, days, tier?, fields: {
    getThere, duration, budget, itinerary: [{day, plan}], pitfalls, food } }
```
理由：静态全量展示不需要槽位抽取机制；`fields` 七个键与 spec 的七字段一一对应，渲染器按键序遍历即可保证"统一顺序"。拥挤度存数字 1~5 由渲染器转星级字符串，保证复制文本与页面显示同源。曾考虑复用 changsha 的 SPOTS 形状，会把简单问题复杂化，弃。`tier: "dream"` 仅遐想档携带（缺省即核心档），渲染器据此在卡头追加徽章。

### D2: 倒计时用纯日期数学，不落 localStorage
`new Date()` 取本地日期，与目标年 10 月 1 日做 UTC 毫秒差换算整数天（先归一化到当天 0 点再相减，规避时区偏移导致的 ±1 天）。分支规则：10.1 前 →"还有 N 天"；10.1~10.7 →"假期进行时"；10.8 后 → 目标年 +1 显示"距下次国庆 N 天"。理由：单日刷新页面重算成本为零，持久化反而引入跨天不更新的 bug；项目内 countdown 游戏是用户自定义目标时间，与此场景不同，不复用其存储。

### D3: 渲染与复制沿用 changsha 模式
单文件 IIFE + `"use strict"`，`render()` 一次性拼 `innerHTML`（数据为自己写死的常量，无注入风险，不做转义过度设计）；复制按钮逐个绑定，`navigator.clipboard.writeText` + `.catch` 降级提示，按钮文案 1.6s 后还原——与 changsha.js L140-149 完全同构。复制文本格式：`【路线名·tagline】` + 每字段一行 `标签：内容` + 署名行"（来自摸鱼大厅 🇨🇳 国庆去哪玩）"。

### D4: 卡片版式与响应式布局（方案 B，用户已选定）
`style.css` 末尾追加 `gq-` 前缀类（gq-card / gq-field / gq-stars / gq-countdown...），结构参照现有 `cs-` 段落，不改任何已有规则；配色全部复用现有变量，不造新色值。
- **布局**：移动优先单列；≥720px 两列网格，八卡呈 2×4；内容列宽 `max-width: 1080px` 居中封顶，超宽屏不拉伸。否决多列并排：七字段含多行 Day 列表，列数一多正文碎成竖条不可读；对比诉求一屏见 2 条完整线已够（手机上下滑动比对）。
- **卡头**：大号 emoji + 线名 + 右侧气质标签（遐想档在线名与标签之间追加"遐想档"虚线描边徽章 .gq-dream）；每张卡顶线 3px 色条区分八线：衡山 --warn / 莽山 --accent / 崀山 --bad / 湄江 --good / 桂林 #35d0c5 / 云南 --accent-2 / 贵州 #8a6a3d（同 .soko-box 既有值）/ 重庆 #fff（雾都，同 .btn.primary 文字色）。
- **字段区**：用 `dl` 定义列表，左标签列约 84px 走 `--mono` 等宽字，弱分隔线不用边框；拥挤度行星级用 --warn 色，星级旁附一句人话（如"人多但山装得下"）。
- **每日安排**：复刻 `cs-stop` 的圆点+竖线时间轴样式（gq- 版本），按 Day1..N 逐行。
- **卡底**：`.btn.primary` 复制按钮居中，下方一行 --text-dim 小字时效声明。
- **倒计时横带**：页头下方通栏居中，大数字复用 `.chip b` 规格；节前 --accent、假期中 --good、节后 --text-dim 三态。
大厅卡片图标用 🇨🇳。

### D5: 文案基调
中文、"摸鱼"语气但信息密度优先——这是发给朋友决策用的，幽默只做佐料（如"坑"字段可写"排队 3 小时起步"式的大实话），不学 fortune 模块整活。

### D6: 核心档/遐想档分层（用户追加方向后澄清）
用户定过"只收高铁 3h 圈"，追加桂林/云南/贵州/重庆时明确意图：不是改规则，是给群友"遐想空间"——不一定真去，摆着让心动有素材。因此不写"范围豁免"，改为显式两档：A~D 核心档（省内 3h 圈，真决策用）、E~H 遐想档（跨省/飞机，心动参考）。实现：数据加 `tier: "dream"`，卡头虚线徽章 + hint 两行定位说明；两档仍共用同一七字段结构，保证可对比。曾考虑物理分区（两个标题块），会破坏 2×4 网格且四卡区显臃肿，弃。

## Risks / Trade-offs

- [票价/班次等旅行信息会过时] → 每张卡底部标注"信息为 2026 年国庆前整理，出行前核实"；数据集中在 `ROUTES` 数组使翻新成本最小。
- [剪贴板 API 在非 HTTPS/旧浏览器不可用] → GitHub Pages 恒为 HTTPS；spec 已要求失败可见提示，最坏情况用户手选文本复制。
- [崀山 4 天是探索阶段的默认假设，若朋友只有 3 天] → 卡片"花几天"字段写明可压缩方案（砍 Day4 夫夷江竹筏），不阻塞实现。莽山、衡山、湄江均为 3 天，无此风险。
- [静态全量页无复玩性，与大厅"游戏"定位略有出入] → 栏目定位就是攻略工具，大厅 README 表格中如实标注玩法为"看攻略 + 复制发群"。

## Migration Plan

纯新增：无数据迁移、无旧行为变更。部署即推 main 走既有 Actions 流水线；回滚 = revert 该提交重新部署。
